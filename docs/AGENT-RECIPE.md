# Operate legends-astro

1. Resolve the selected module source and user workspace (`legends-astro resources --json` and `legends-astro knowledge-pack --check --json`). Never save migration contracts, captures, twin screenshots, or site outputs into a managed module source.
2. Run `legends-astro doctor --json` (and `--project <astro-dir>` when inspecting an existing Astro site). This is offline, checks Node (`>=22.23.4`, LTS `24.15.0` tested) and local `astro` (`7.4.13` canary baseline) versions, checks for global `astro` PATH collisions, verifies the vendored `withastro/docs` snapshot, flags Astro v7 Content Layer traps (`src/content/config.ts` vs `src/content.config.ts`), and reports read-only optional `ecosystem` availability (`legends-firecrawl`, Playwright). It never executes consumer `astro.config.*` files.
3. Choose the matching entry command:
   - **Greenfield Day-1 starter (no existing site):** preview with `legends-astro init --output <astro-dir> [--name <brand>] [--site <url>] [--preset agency|blog|local-business] [--trailing-slash always|never|ignore] [--with-sitemap|--no-sitemap] [--staging-lock]` (or `legends-astro scaffold --output <astro-dir> --mode starter` with the same flags), then apply with `--apply --confirm-plan <planSha256>`. See `wiki/agency-starter-guidelines.md`.
   - **Existing framework codebase (Next.js App/Pages Router, Nuxt, Gatsby, Vite/CRA React/Vue/Svelte SPA, Docusaurus, Hugo, Jekyll, Eleventy, SvelteKit):** run `legends-astro source-audit --source <repo-dir> --output <contract.json>` (strictly read-only static inspection; never executes repo configs) to extract `frameworkMigration` (routes, API routes, redirects, interactive islands vs static `.astro` candidates, `PUBLIC_*` env var renames, framework import traps, content collections, and exact vendored `docs-lookup` IDs).
   - **Live website or `legends-firecrawl` archive:** run `legends-astro capture --url <origin> --from-sitemap --crawl --output <work-dir>` (or `--from-firecrawl <file-or-dir>`) to collect `raw-capture/`, `migration-contract.json`, a Migration Triage Report, and `firecrawlFallback`. If live HTTP capture reports `firecrawlFallback.recommended == true` (WAF/bot challenge such as Cloudflare 403/503/429 or empty JS SPA shell), capture via optional `cto-legends run legends-firecrawl` (`formats: ["rawHtml", "markdown"]`) and re-run `legends-astro capture --from-firecrawl <capture-dir> --output <work-dir>`.
   - **Static HTML or WordPress WXR `.xml` / REST `.json` export:** run `legends-astro source-audit --source <path> --output <contract.json>`.
4. When localizing remote CDN, WordPress (`/wp-content/`, `/wp-includes/`), or Webflow assets, run `legends-astro vendor-assets --source <raw-capture> --output <astro-dir> --allow-host <host> [--dry-run]` to perform Pass 1 HTML extraction and Pass 2 recursive CSS `@import`/`url(...)` downloading into `public/` and `asset-map.json`.
5. Preview Astro v7.4.13 scaffolding with `legends-astro scaffold --source <path> --output <astro-dir> --mode clone|editorial|starter [--asset-map asset-map.json] [--decode-cf-email] [--strip-trackers] [--staging-lock]` (or `legends-astro ingest` for Content Layer collection-only scaffolding) to inspect `plannedFiles` and `planSha256`. Only pass `--apply --confirm-plan <planSha256>` (and `--overwrite` if replacing existing files) when writes are authorized.
6. In Astro v7 projects, define collections at `src/content.config.ts` using `glob()` from `astro/loaders` and `z` from `astro/zod`, use `entry.id` instead of `entry.slug`, and filter with shared `isPublished` (drafts plus future `pubDate` in production) in listings, `getStaticPaths()`, and RSS.
7. For Day-2 publishing on an existing Astro project, use `legends-astro post --project <astro-dir> --list` (read-only inventory), preview a create with `--input <article.md> [--hero <img> --hero-alt <text>] [--publish|--draft]`, update with `--slug <slug> --update --input <article.md>` (preserves `pubDate`, stamps `updatedDate`), or rename with `--rename-from <old> --slug <new>` (deduplicated `301` in `public/_redirects`). Only pass `--apply --confirm-plan <planSha256>` when writes are authorized. See `wiki/publishing-and-content-ops.md`.
8. After `ASTRO_TELEMETRY_DISABLED=1 node ./node_modules/astro/bin/astro.mjs build`, run `legends-astro verify-build --dist <dist-dir> --project <astro-dir> --contract <contract.json> [--forbid-host <cdn>] [--env staging|production]` to verify route parity, zero draft leakage, SEO/canonical/OG/JSON-LD/H1/Webflow `data-wf-page` parity, client-JS DOM IDs, first-paint `<head>` CSS order, CSS `url()`/`@import` resolution, local SRI cleanup, XXE-safe sitemaps, `_redirects`, and staging/production env locks. For Day-2 changes, record the first production baseline with `--write-manifest site-manifest.json --env production`, then gate every later build with `--baseline site-manifest.json --write-manifest site-manifest.json --overwrite --env production` (plus `--allow-canonical-change` only when a canonical move is authorized).
9. When visual proof is requested and optional Playwright is installed, capture a Visual Digital Twin via `legends-astro twin --dist <dist-dir> --output <twin-dir>` (ephemeral in-process `127.0.0.1:0` read-only server closed in `finally`) or `--url <https://...> --allow-host <domain>`, and compare baseline vs candidate offline with `legends-astro twin-diff --baseline <a/twin.json> --candidate <b/twin.json>`. Never spawn detached background `astro dev` or `astro preview` servers or pass `--open`.
10. Use `legends-astro docs-lookup "<query>" --live-locations` to search the vendored `withastro/docs` MDX guides (covering all official framework migration guides) and `wiki/` runbooks. Note that `https://docs.astro.build/llms.txt` and `/llms-full.txt` return HTTP 404 upstream; use `docs-lookup` or raw GitHub MDX files.
11. Save a private migration receipt only when requested or part of an authorized Empire workflow (`templates/migration-receipt.md`).

Do not install a standalone module skill. The central `cto-legends` skill loads this recipe on demand.

## EDR and Security Guardrails

- Never spawn hidden consoles, execution-policy bypass shell wrappers, or detached background localhost daemons.
- Never read local browser profile databases, cookie stores, `Login Data`, or OS credential stores.
- Never print raw API keys, tokens, or secrets to stdout, stderr, or Markdown receipts.
