# Operate legends-astro

1. Resolve the selected module source and user workspace (`legends-astro resources --json` and `legends-astro knowledge-pack --check --json`). Never save migration contracts, captures, twin screenshots, or site outputs into a managed module source.
2. Run `legends-astro doctor --json` (and `--project <astro-dir>` when inspecting an existing Astro site). This is offline, checks Node (`>=22.23.4`, LTS `24.15.0` tested) and local `astro` (`7.4.13` canary baseline) versions, checks for global `astro` PATH collisions, verifies the vendored 36-file `withastro/docs` snapshot (33 MDX guides), and flags Astro v7 Content Layer traps (`src/content/config.ts` vs `src/content.config.ts`). It never executes consumer `astro.config.*` files.
3. For live site or `legends-firecrawl` migrations, run `legends-astro capture --url <origin> --from-sitemap --crawl --output <work-dir>` (or `--from-firecrawl <file-or-dir>`) to collect `raw-capture/`, `migration-contract.json`, and a deterministic Migration Triage Report. For static HTML or WordPress WXR `.xml` / REST `.json` exports, run `legends-astro source-audit --source <path> --output <contract.json>` first.
4. When localizing remote CDN, WordPress (`/wp-content/`, `/wp-includes/`), or Webflow assets, run `legends-astro vendor-assets --source <raw-capture> --output <astro-dir> --allow-host <host> [--dry-run]` to perform Pass 1 HTML extraction and Pass 2 recursive CSS `@import`/`url(...)` downloading into `public/` and `asset-map.json`.
5. Preview Astro v7.4.13 scaffolding with `legends-astro scaffold --source <path> --output <astro-dir> --mode clone|editorial [--asset-map asset-map.json] [--decode-cf-email] [--strip-trackers] [--staging-lock]` (or `legends-astro ingest` for Content Layer collection-only scaffolding) to inspect `plannedFiles` and `planSha256`. Only pass `--apply --confirm-plan <planSha256>` (and `--overwrite` if replacing existing files) when writes are authorized.
6. In Astro v7 projects, define collections at `src/content.config.ts` using `glob()` from `astro/loaders` and `z` from `astro/zod`, use `entry.id` instead of `entry.slug`, and filter `draft !== true` in both index listings and `getStaticPaths()`.
7. After `ASTRO_TELEMETRY_DISABLED=1 node ./node_modules/astro/bin/astro.mjs build`, run `legends-astro verify-build --dist <dist-dir> --project <astro-dir> --contract <contract.json> [--forbid-host <cdn>] [--env staging|production]` to verify route parity, zero draft leakage, SEO/canonical/OG/JSON-LD/H1/Webflow `data-wf-page` parity, client-JS DOM IDs, first-paint `<head>` CSS order, CSS `url()`/`@import` resolution, local SRI cleanup, XXE-safe sitemaps, `_redirects`, and staging/production env locks.
8. When visual proof is requested and optional Playwright is installed, capture a Visual Digital Twin via `legends-astro twin --dist <dist-dir> --output <twin-dir>` (ephemeral in-process `127.0.0.1:0` read-only server closed in `finally`) or `--url <https://...> --allow-host <domain>`, and compare baseline vs candidate offline with `legends-astro twin-diff --baseline <a/twin.json> --candidate <b/twin.json>`. Never spawn detached background `astro dev` or `astro preview` servers or pass `--open`.
9. Use `legends-astro docs-lookup "<query>" --live-locations` to search the 33 vendored `withastro/docs` MDX guides and 9 `wiki/` runbooks. Note that `https://docs.astro.build/llms.txt` and `/llms-full.txt` return HTTP 404 upstream; use `docs-lookup` or raw GitHub MDX files.
10. Save a private migration receipt only when requested or part of an authorized Empire workflow (`templates/migration-receipt.md`).

Do not install a standalone module skill. The central `cto-legends` skill loads this recipe on demand.

## EDR and Security Guardrails

- Never spawn hidden consoles, execution-policy bypass shell wrappers, or detached background localhost daemons.
- Never read local browser profile databases, cookie stores, `Login Data`, or OS credential stores.
- Never print raw API keys, tokens, or secrets to stdout, stderr, or Markdown receipts.
